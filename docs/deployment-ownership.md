# 배포 사이트 소유권 확인

기존 GitHub OAuth, GitHub App, 저장소 권한 검사와 코드 수집 경로를 유지한다.
이 기능은 등록한 사이트에서 확인 파일을 제공할 수 있는지만 확인하며,
실제 공격 테스트, Vercel 계정 소유권 또는 GitHub 커밋과 배포의 일치를 확인하지 않는다.
`testRequestsAllowed`는 소유권 확인 후에도 항상 `false`다.

## DB 적용 준비

이번 구현에서는 DB 조회·마이그레이션·Prisma Client 생성을 실행하지 않았다.
확인한 마이그레이션 SQL에는 기존 행/테이블/필드를 삭제하는 구문이 없다.
실제 DB의 적용 이력과 스키마 차이는 별도 확인이 필요하다.

- `20261117000100_repository_deployment`: URL과 검증일은 nullable, 상태는
  `UNVERIFIED` 기본값으로 추가된다. 기존 연결 데이터는 그대로 유지된다.
- `20261117000200_deployment_ownership_challenge`: nullable 토큰 해시·만료일·발급일·다음 확인일,
  기본값 0인 버전과 시도 횟수, 빈 사용자별 제한 테이블을 추가한다.
- 새 제한 테이블의 `ON DELETE CASCADE`는 향후 사용자가 삭제될 때 제한 기록만 정리한다.
  마이그레이션 실행 시 사용자를 삭제하지 않는다.
- `ALTER TABLE` 실행에는 잠금이 필요할 수 있다. 적용 전 대상 DB와 백업을 확인한다.

루트 `prisma.config.ts`는 `.env`를 읽고 `DIRECT_DATABASE_URL`을 우선 사용하며,
없으면 `DATABASE_URL`을 사용한다. 기존 스크립트로 적용한다:

```powershell
npm.cmd run db:deploy
npm.cmd run db:generate
```

`db:deploy`는 모든 미적용 마이그레이션을 적용하고, `db:generate`는 로컬 Prisma Client를
재생성한다. 데이터 삭제를 요구하는 reset이나 `db push`는 필요하지 않다.
두 단계가 끝나기 전에는 새 DB 필드를 사용하는 기능을 실행하지 않는다.

## 사용자 흐름

1. 기존 `/repository?connected=연결ID` 상세 화면에서 배포 URL을 저장한다.
2. 검증 토큰 발급 버튼을 누른다. 토큰 원문은 응답과 화면에 한 번만 제공하고 서버에는
   사용자 ID·연결 ID·저장소 ID·등록 URL에 결합된 SHA-256 해시만 저장한다.
3. 화면에 표시된 텍스트를 `public/.well-known/vulnlab-ownership.txt`에 저장하고
   사이트를 배포한다. 다른 프레임워크는 해당 정적 파일 제공 폴더를 사용한다.
4. 소유권 확인 버튼을 누른다. 확인 파일은 HTTPS에서 리다이렉트·로그인 없이 HTTP 200으로
   반환되어야 한다. 내용은 토큰 텍스트와 선택적인 앞뒤 공백/줄바꿈만 허용된다.
5. 성공하면 `VERIFIED`와 확인 시각을 저장하고 토큰을 소모한다. 확인 파일은 제거해도 된다.

토큰은 256비트 난수, 유효기간 15분, 토큰당 확인 5회다. 재발급 간격은 60초,
확인 간격은 10초이며 사용자별 1시간 창에서 발급 10회·확인 30회로 제한한다.
제한은 DB의 조건부 갱신으로 적용되므로 URL 변경·재발급·다중 서버로 초기화되지 않는다.
URL 재저장/변경과 토큰 재발급은 기존 소유권 상태 및 토큰을 무효화한다.
검증 완료 직전 GitHub 접근 권한을 재확인하고 URL·버전·토큰·시도 번호·만료 시각이
일치할 때만 DB를 갱신한다.

## 확인 요청의 범위와 제한

- Node.js 런타임에서만 동작한다. 요청 경로는 고정된 `/.well-known/vulnlab-ownership.txt`다.
- 확인할 때마다 A 레코드를 새로 조회한다. 반환된 IPv4 중 사설·루프백·링크 로컬·메타데이터·
  특수 목적 주소가 있으면 차단한다. IPv6 연결이나 자동 주소 대체는 사용하지 않는다.
- 검사한 IP 리터럴로 직접 HTTPS 443에 연결한다. 다시 DNS를 조회하거나 환경 프록시로
  우회하지 않는다. 원래 호스트명을 Host/SNI/인증서 이름 확인에 사용하며 TLS 검증을 유지한다.
- 리다이렉트·재시도·다른 경로 탐색·쿠키·GitHub 토큰 전달을 하지 않는다.
- DNS 최대 3초, HTTPS 전체 최대 5초, 응답 헤더 최대 8KB, 본문 최대 1KB다.
  압축 응답을 허용하지 않으며 잘리거나 실패한 응답은 검증하지 않는다.

IPv6 전용 사이트, 배포 보호/로그인이 필요한 사이트, 확인 경로를 리다이렉트하는 사이트는
지원하지 않는다. 검증은 해당 시점의 사이트 제어 증명이며 영구 소유권 증명이 아니다.
운영 환경에는 별도의 송신 네트워크 제한도 권장한다. 애플리케이션은 호스트 네트워크의
특수 라우팅·투명 프록시까지 보증할 수 없다. 실제 테스트 기능을 연결할 때는 소유권 재검증,
허용 범위 및 커밋/배포 일치 확인, 격리된 실행 환경과 별도 송신 정책이 필요하다.

테스트·빌드·실제 사이트 확인 요청은 이번 작업에서 실행하지 않았다.
