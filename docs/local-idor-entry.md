# 메인 화면에서 로컬 IDOR 실습 열기

메인 화면의 **공격 실습 둘러보기 → IDOR Local Lab** 또는 사이드바의 **공격 실습**으로 `/practice`에 진입합니다. IDOR 카드 또는 로컬 실습 안내의 **IDOR 실습 열기 (새 탭)** 링크는 `http://127.0.0.1:4400/lab/idor`를 엽니다. 실습 화면과 인증은 기존 `labs/basic-site`를 그대로 사용합니다.

## 실행

Node.js 24.14 이상에서 별도 PowerShell 터미널을 사용합니다.

```powershell
Set-Location D:\likelion-repo
$env:NODE_ENV = "development"
$env:BASIC_SITE_ENABLE_IDOR = "1"
$env:BASIC_SITE_PORT = "4400"
npm.cmd --prefix labs/basic-site start
```

메인 프론트엔드는 프로젝트 루트에서 `npm.cmd run dev`로 실행합니다. 기존 서버가 IDOR 비활성 상태라면 해당 터미널에서 Ctrl+C 후 위 설정으로 다시 시작합니다.

## 상태 확인

사용자 브라우저가 `http://127.0.0.1:4400/api/health`를 페이지 진입 및 **상태 다시 확인** 클릭 시 조회합니다. 3초 제한, 캐시 미사용, 인증정보 미전송이며 서비스 식별자와 `idorEnabled`를 검사합니다. 서버 실행·IDOR 활성, 서버 실행·IDOR 비활성, 연결 확인 불가를 구분합니다. 상태는 조회 시점 기준이며 자동 폴링하지 않습니다.

헬스 응답에만 인증정보 없는 CORS 읽기를 허용합니다. 게시글·인증·취약 API의 CORS 및 Host/Origin 검증은 유지합니다. 서버가 꺼져 있거나 응답이 잘못됐거나 브라우저가 로컬 접근을 차단하면 연결 확인 불가와 실행 명령을 표시합니다. 링크는 직접 확인할 수 있도록 유지하며 서버가 꺼져 있으면 새 탭에 브라우저 연결 오류가 표시됩니다.

## 검증

- 자동 테스트: 메인 진입 링크, 새 탭 및 noopener/noreferrer, 로컬 안내, 활성/비활성/잘못된 응답/통신 오류/시간 초과 상태, 실제 HTTP 헬스 응답 및 다른 API에 CORS가 추가되지 않았는지 검사합니다.
- 수동 브라우저 절차: 실습 서버를 끄고 메인 → 공격 실습에서 연결 확인 불가 및 실행 명령 확인 → 서버 실행 → 상태 다시 확인 → 실행 중 표시 확인 → IDOR 링크 클릭 → 별도 탭 주소와 기존 실습 화면 확인 → 기존 메인 탭 유지 확인. IDOR 플래그를 끈 상태로 재시작해 비활성 안내도 확인합니다.
- 이번 실행의 브라우저 도구는 접근 승인 대기 시간 초과로 실제 클릭 검증을 완료하지 못했습니다. 자동 테스트는 실제 브라우저 검증을 대체하지 않습니다.

## 실제 배포 전

현재 주소는 각 사용자 자신의 PC를 가리키며 공용 실습을 자동 제공하지 않습니다. 로컬 방식으로 배포하려면 사용자별 설치·실행 안내와 HTTPS 페이지에서의 브라우저 로컬 네트워크 접근 정책을 검증해야 합니다. 공용 실습을 제공하려면 사용자별 격리 환경, 실습 수명·초기화 관리, 별도 실습 도메인 및 인증·접근 정책, 상태 확인·URL 설정을 설계해야 합니다. 현재의 개발 전용 취약 서버를 그대로 외부에 공개하면 안 됩니다.

기존 `/security-lab` 주문 예제, Runner, GitHub 로그인, Prisma, RepoTutor 구현은 이 연결 작업에서 변경하지 않습니다.
