## 화면별 변경

### 공통

- 차콜, 크림, 올리브 팔레트와 기존 밝은 카드·얇은 테두리를 재사용했다.
- 앱 콘텐츠의 최대 너비를 1,240px로 조정하고 상단 여백을 기존 56px에서 기본 32px로 축소했다. 중간 화면은 28px, 모바일은 24px를 사용한다.
- 가로 패딩과 카드 간격을 화면 크기에 맞게 조정했다.
- 랜딩과 앱이 같은 액션 버튼 스타일과 색상 변수를 공유한다. 랜딩의 강한 초록, 그라데이션, 입체 변형 및 그림자 미리보기를 제거했다.
- 패키지, 이미지, 외부 폰트는 추가하지 않았다.

### 로그인 후 홈

- 인사말을 ‘반가워요, 표시 이름’으로 변경해 영문 표시 이름 뒤에 한국어 접미사가 붙지 않도록 했다. 긴 이름은 줄바꿈할 수 있다.
- 두 주요 카드를 제목·본문·하단 액션으로 나누어 같은 행의 높이와 버튼 위치를 맞췄다. 고정 높이를 강제하지 않아 내용과 이름 길이에 맞게 늘어난다.
- 학습 기록이 없는 경우, 접근 가능한 연결이 없는 경우, 실제 기록이 있는 경우의 기존 데이터 분기를 유지했다.
- 최근 활동은 제목/저장소, 날짜, 이동 링크의 그리드로 정렬했다. 모바일에서는 제목 아래에 날짜와 액션이 나란히 배치된다.
- 이전에 추가한 권한 동기화, 사용자 범위의 DB 조회와 학습 위치 링크 생성 로직은 유지했다.

### 내 저장소

- 정상 연결은 ‘GitHub 연결됨 · 계정명’ 형태의 작은 상태 영역으로 표시한다. 계정이 여러 개면 첫 계정과 나머지 개수를 표시하고 전체 정보는 펼침 영역에 제공한다.
- 정상 상태의 ‘연결 설정’은 기본 접힘이다. 설치 관리, 권한 동기화, 설치별 상태·동기화 시각과 조직 권한 안내를 필요할 때 펼칠 수 있다.
- 설치가 없거나 일시 중지됐거나 연결 저장소가 없으면 안내와 해결 액션을 기본으로 펼쳐 보여준다. 계정의 설치 사실만으로 저장소 접근 가능 상태를 단정하지 않는다.
- 기존 GitHub App 연결 경로와 refreshRepositories 서버 액션을 그대로 사용한다. 권한 검사·동기화 로직은 변경하지 않았다.
- 저장소 행을 정보, 분석 상태, 액션 영역으로 정리했다. 소유자, 이름, 공개 범위, 기본 브랜치, 분석 종료 시각의 정보 계층을 구분했다.
- ‘분석 결과 보기/다시 분석하기/분석 시작’과 관리 메뉴를 같은 액션 영역에 배치했다.
- 중간 화면에서는 정보를 위에, 상태와 액션을 아래에 배치한다. 작은 모바일에서는 세 영역을 차례로 쌓고 버튼이 줄바꿈할 수 있도록 했다.
- 검색·필터·정렬, 분석 중 버튼 제한·상태 갱신, 중지된 설치의 액션 제한, 실패 재시도, 연결 없음·검색 결과 없음 상태를 유지했다.

### 비로그인 랜딩

1. 소개: 코드 읽기의 시작을 돕는 학습 공간이라는 메시지와 GitHub 시작·데모 분석 CTA.
2. 문제: 읽기 시작점, 함수 사이의 연결, 코드 이해의 어려움을 설명하는 세 카드.
3. 학습 과정: 저장소 연결 → 기능·함수 선택 → 코드 관계 탐색 → AI 설명.
4. 시각 예시: 기존 샘플 코드의 LoginPage, handleLogin, login을 바탕으로 재구성한 정적인 설명 그림. ‘예시 화면’ 배지와 실제 분석 화면이 아니라는 안내를 표시했다. 그래프가 전체 실행 순서를 보장하지 않는다는 문구도 포함했다.
5. 구현 범위: 현재 가능한 코드 구조·관계 탐색 및 연결 저장소 AI 학습과, 향후 목표인 입력→화면→API→서버→DB 전체 흐름 분석을 별도 카드로 구분했다. 준비 중 기능도 명시했다.
6. 마지막 시작 안내: GitHub 로그인과 로그인 없는 샘플 데모 진입 경로를 다시 제공했다.

랜딩 그림은 HTML/CSS로 만든 설명용 요소이며 실제 그래프 컴포넌트·분석 결과를 대체하지 않는다. 실제 코드 탐색 화면과 분석 알고리즘은 수정하지 않았다.

## 검증 결과

| 검사 | 결과 |
| --- | --- |
| npm.cmd run typecheck | 통과 |
| npm.cmd run lint | 통과, 경고·오류 없음 |
| npm.cmd test | 316개 통과, 5개 건너뜀; 30개 파일 통과, 4개 파일 건너뜀 |
| npm.cmd run build | 통과; 프로덕션 컴파일·타입 검사·페이지 생성 완료 |
| git diff --check | 통과 |

건너뛴 5개는 기존 외부 연동 테스트 설정에 따른 결과다. 실제 GitHub 서비스의 인증·권한 검증을 수행했다는 의미가 아니다.

PowerShell의 npm.ps1 실행 정책 때문에 npm.cmd를 사용했다. 테스트와 빌드는 하위 프로세스 실행이 가능한 환경에서 실행했다. 빌드·타입 검사로 자동 변경된 next-env.d.ts와 tsconfig.tsbuildinfo는 작업 전 상태로 복구했다.

### 직접 수행한 로컬 HTTP 확인

기존 개발 서버 http://localhost:3000에 인증 쿠키 없이 요청했다. 기존 서버를 중지하거나 교체하지 않았다.

| 경로 | 결과 |
| --- | --- |
| / | 200, 개편 랜딩의 마크업과 로그인·데모 링크 확인 |
| /login | 200 |
| /repository | 200 |
| /api/analyze?source=sample | 200, 샘플 분석 응답 확인 |
| /dashboard | 307, /login?callbackUrl=%2Fdashboard |
| /repositories | 307, /login?callbackUrl=%2Frepositories |

HTTP 결과는 브라우저의 렌더링·클릭·JavaScript 동작을 검증한 결과와 구분한다.

### 직접 확인하지 못한 브라우저 동작

브라우저 자동화 도구가 ‘The browser access host is unavailable’ 오류를 반환하여 시각적 브라우저 검수는 수행하지 못했다.

- 실제 데스크톱·모바일 너비에서 줄바꿈, 스크롤, 버튼/메뉴 겹침 여부
- 로그인 후 실제 계정 이름과 학습 기록이 표시된 홈
- 실제 설치/조직/연결 저장소가 있는 상태의 목록과 다중 계정 표시
- 연결 설정 펼침/접힘, 관리 메뉴, 검색·필터·정렬의 브라우저 클릭 동작
- 랜딩의 앵커 이동과 키보드 포커스, 실제 데모 그래프의 클라이언트 렌더링
- GitHub 로그인 리다이렉트, App 설치·권한 설정으로 이동하는 외부 흐름

위 항목은 완료했다고 간주하지 않는다. 반응형 CSS와 기존 자동 테스트는 적용·검증했으며 실제 브라우저 E2E·시각 검수는 별도로 필요하다.
