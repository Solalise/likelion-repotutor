# SQLi 요청 편집기 MVP (화면 전용)

## 범위

GET 요청과 쿼리 파라미터 1개를 대상으로 정상 입력값·테스트 입력값을 각각 편집하고 인코딩된 요청 미리보기를 제공한다. 정상 응답과 테스트 응답은 데스크톱에서 나란히, 좁은 화면에서는 세로로 표시한다. HTTP 상태 코드, 응답 시간, 요청 상태, 오류, 텍스트 본문과 잘림 여부를 구분한다.

외부 요청 API, 실행기, fetch 이벤트, 자동 공격, 가짜 실행 결과를 포함하지 않는다. 실행 버튼은 항상 비활성화되고 `테스트 실행 환경 연결 전`으로 표시된다. 기존 GitHub 분석·Vercel 메타데이터 조회 API는 그대로 유지한다. XSS 편집기는 추가하지 않았다.

## 사용 경로

1. `/services` → GitHub 연결 저장소 선택 (`/services?connected=<connectionId>`).
2. 저장소 분석 실행 또는 분석 결과 조회 → SQL Injection 후보 선택.
3. 실습 대상 API 확인 → 메서드 `GET`, 입력 위치 `query`, 경로·파라미터·기준값 확인 → 확인 체크.
4. 실습 준비 화면으로 이동 → `SQLi 요청 편집기로 이동`.
5. 정상값·테스트값 편집 및 두 요청 미리보기 확인. 응답 비교는 `미실행`, 상태 코드는 `응답 없음`, 시간은 `측정되지 않음`이다. 테스트 입력 초기값은 빈 문자열이며 예시 공격 문자열을 자동 생성하지 않는다.
6. 실습 준비로 돌아가거나 대상 수정 가능. 편집기에서 돌아갔다가 재진입하면 기준 입력으로 초기화되며 저장 기능은 없다.

별도 페이지 URL은 추가하지 않았다. 기존 준비 화면 안에서 전환한다. GET/query 이외 대상은 지원 범위를 안내하고 경로를 추측해 변경하지 않는다. 기존 후보 0개·API 미확정 안내를 재사용한다.

## 분리한 인터페이스

`src/lib/security-lab/sqliTypes.ts`:

- `SqliRequestDraft`: 버전, 사용자 저장소 연결 ID, 저장소, 분석 SHA, 후보 ID, 배포 origin, API 경로, GET, query 파라미터, 정상값과 테스트값. 인증 쿠키·토큰 필드가 없다.
- `SqliResponseEvidence`: 요청 ID, 관찰 시각, 응답/연결 실패/시간 초과/접근 거부/차단 구분, nullable HTTP 상태·시간·본문, 본문 잘림, nullable 오류 메시지.
- `SqliComparisonResult`: 실행 ID, 실행에 사용한 요청 스냅샷, 정상·테스트 응답, 판정과 근거 참조. 편집 중인 입력과 과거 응답을 혼합하지 않도록 요청 스냅샷을 포함한다.
- `SqliAssessmentStatus`: `NOT_RUN`(미실행), `INCONCLUSIVE`(판정 불가), `VULNERABILITY_CONFIRMED`(취약점 확인), `NO_VULNERABLE_BEHAVIOR_OBSERVED`(취약 동작 미관찰).
- `sqliDisplayAssessment`: 결과가 없으면 미실행. 검증된 서버 판정 어댑터가 없는 현재 단계에서는 결과 객체가 전달되어도 판정 불가. 마지막 두 상태는 계약·표시 이름만 준비했고 실제 선택/승격 기능은 제공하지 않는다.
- `sqliRequestPreview`: URLSearchParams로 입력값을 하나의 값으로 인코딩하는 순수 함수. 요청을 전송하지 않는다.

`SqliResponseComparison`은 실행 기능과 분리된 표시 컴포넌트다. 앱은 현재 `result={null}`을 전달한다. 테스트 fixture는 테스트 파일에만 있으며 제품 화면에 주입되지 않는다. 본문은 React 텍스트로 렌더링해 HTML/스크립트를 실행하지 않는다.

## 격리 실습 서버 연결 시 필요한 작업

1. 서버에서 연결 사용자·저장소·분석 SHA·후보 ID와 요청을 검증하는 어댑터 구현. 브라우저의 draft나 판정 값을 승인 근거로 신뢰하면 안 된다.
2. 소유권과 별도의 격리 환경 승인, 비운영 데이터/읽기 전용 DB/API 검토, 정확한 origin·경로·메서드·파라미터 허용 정책 마련.
3. DNS/IP 고정과 내부망 차단, redirect 금지, 요청 수·시간·응답 크기 제한을 갖춘 서버 실행기 구현. 대상에 인증 쿠키·GitHub/Vercel 토큰 전달 금지.
4. 실제 응답을 위 evidence 계약에 매핑하고 요청 스냅샷·실행 ID에 연계. 응답 형식/길이 검증과 민감 데이터 처리를 추가.
5. 서버의 검증된 판정 근거·증거 참조를 확인하는 어댑터를 추가한 뒤에만 마지막 두 판정 상태 활성화. 단순 HTTP 상태·시간·본문 차이는 SQLi 증명이 아니다.

현재는 이 서버 연결이 없으므로 소유권이 확인되어도 실행할 수 없다.

## 검증 결과

- `npx.cmd vitest run src/components/repository/SqliRequestEditor.test.tsx`: 관련 테스트 2개 통과 (미실행/비활성 버튼/요청 인코딩/네트워크 호출 없음, 응답 비교·오류·텍스트 이스케이프·검증되지 않은 판정 차단).
- `npx.cmd tsc --noEmit --incremental false`: 기존 `src/lib/github/repositoryMetadataAccess.test.ts` 29·45행 TS2554 두 건. 이번 변경 파일에서 타입 오류는 보고되지 않았다.
- 로그인 브라우저의 실제 탐색은 검증하지 않았다. 초기 화면 및 응답 표시 컴포넌트는 서버 렌더링으로 검증했다.
- 전체 테스트·빌드·ESLint·DB 마이그레이션·Git commit/push는 실행하지 않았다.
