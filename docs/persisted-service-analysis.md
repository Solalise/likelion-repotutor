# 내 웹서비스 분석 결과 영구 저장

## 적용

`AnalysisRun`에 nullable JSONB 필드 `analysis_result`, `review_guide`만 추가합니다. 기존 이력·통계·학습 설명·수동 관찰 기록을 삭제하거나 변경하지 않습니다.

이번 작업에서는 **DB 마이그레이션을 적용하지 않았습니다.** 배포 대상 DB를 확인한 환경에서 다음을 실행한 뒤 새 앱을 실행하세요.

```powershell
npx.cmd prisma migrate deploy
npx.cmd prisma generate
```

클라이언트 생성은 개발 작업 중 실행했습니다. 기존 이력에는 상세 결과가 없으므로 소급 복원할 수 없습니다. 변경 적용 후 한 번 수동 분석하면 이후부터 자동 복원됩니다. 기존 수동 기록은 보존되며 동일 커밋·환경에서 다시 연결됩니다.

## 저장 및 복원

- 성공한 분석 실행마다 기존 `AnalysisRun`에 저장 포맷 버전, 분석기 버전, 기술 스택, 통계, 유형별 결과, 파일·줄 번호, 제한된 코드 근거, 기본 가이드를 기록합니다. 커밋은 `commitSha`, 분석 일시는 `completedAt`과 연결합니다.
- 전체 파일·함수·노드의 `sourceCode`는 빈 문자열로 저장합니다. 코드 근거는 길이를 제한하고 리터럴·주석·인증정보·환경변수 참조를 제거합니다. 원본 패키지 매니페스트는 저장하지 않습니다.
- 기존 가이드 API의 서버 검증이 성공한 AI 가이드만 같은 실행의 `review_guide`에 추가 저장합니다. 응답 원문은 저장하지 않으며, 기본 가이드 응답으로 기존 AI 가이드를 덮어쓰지 않습니다. 기존 `LearningRecord` 저장/검증 로직은 그대로 사용합니다.
- 화면 진입 시 `GET /api/repositories/{connectionId}/analysis`가 현재 사용자·저장소의 마지막 성공 결과를 읽습니다. 실패 실행은 선택하지 않습니다. 메모리 캐시나 소스 다운로드·AST·Groq에 의존하지 않습니다. 기존 GitHub 접근 권한은 조회 전후 확인합니다.
- 수동 기록과 진행률은 기존 `SecurityTestRecord` 조회를 통해 저장소·커밋 SHA·연결 ID·환경 버전 및 대상 일치 조건으로 복원합니다. 다른 환경의 기록을 현재 진행률로 합치지 않습니다.
- 저장된 AI 가이드는 가이드 요청에서도 먼저 반환합니다. AI 가이드가 없고 메모리가 만료되었으면 저장된 기본 가이드를 반환하며 자동 재분석하지 않습니다.

## 직접 확인

1. 마이그레이션 적용 후 저장소를 한 번 분석합니다. 통계·커밋·분석 일시를 확인합니다.
2. 동일 커밋·등록 환경에서 수동 관찰을 저장하고 진행률을 확인합니다. AI 설명은 확장 연결 시 기존 가이드 생성 경로로 생성·검증·저장됩니다.
3. 새로고침, 로그아웃/재로그인, 서버 재시작 후 다시 진입합니다. 결과·가이드·기록을 확인합니다. 네트워크에는 복원용 `/analysis`와 기존 권한/환경/기록 요청만 발생하고 `/analyze`는 자동 호출되지 않아야 합니다.
4. 재분석을 실패시킨 뒤 재진입해 이전 성공 결과가 유지되는지 확인합니다.
5. 미분석 저장소에서는 최초 분석 안내, 조회 오류에서는 조회 실패와 다시 조회 버튼이 표시되는지 확인합니다.
6. 저장소 권한을 철회하거나 다른 사용자의 연결 ID로 요청했을 때 저장 결과가 반환되지 않는지 확인합니다.

전체 테스트·ESLint·TypeScript 검사·전체 빌드는 요청에 따라 생략했습니다. 실제 브라우저·운영 DB 테스트는 별도 수행이 필요합니다.
